# ops/lib/project

## Purpose
Source files for the project lane. Nothing here executes; the binaries that read these files are `ops/bin/scaffold` and `ops/bin/bundle` (through `ops/bin/meta`).

## Structure
- `SCAFFOLD.md`: the scaffold spec. `ops/bin/scaffold <name>` creates one directory for every `- <dirname>/` line and copies the file into the new project as `projects/<name>/SCAFFOLD.md`.
- `STELA.md`: the project contract template. Copy it to `projects/<name>/STELA.md`; `docs/MAP.md` discovers projects by that file and `tools/lint/project.sh` validates the registry identifiers it names.
- `README.md`: this file.

## Entry Point
Run every project binary from the repository root; the lifecycle steps and the bundle call are in `projects/README.md`.

## Constraints
- The shell helper library for project binaries is `ops/lib/scripts/project.sh` (repo-root and project-identifier guards), registered in `docs/ops/registry/scripts.md`; it does not live in this folder.
- Edit these two source files only through a packet that names them; a scaffolded project carries copies, not links.

## Canonical Pointer
`docs/ops/registry/projects.md` is the registry of record; `docs/MAP.md` is generated by `./ops/bin/map`.

## Where to Look Next
- `projects/README.md` for the lane's lifecycle.
- `docs/ops/specs/binaries/scaffold.md` for what the scaffold binary writes.
- `docs/ops/specs/tools/lint/project.md` for the identifier checks on a project contract.
