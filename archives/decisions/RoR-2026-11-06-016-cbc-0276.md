## Context

Tool or binary under review: ops/lib/scripts/bundle.sh

## CbC Preflight Questions

**Q1: Is structural prevention viable instead of detection?**
Yes, and taken. The profile is policy-driven like the other five: its keys, stance, artifact prefix, dump scope, and persistence depth come from `ops/lib/manifests/BUNDLE.md` and `ops/etc/persistence.manifest`, so a profile with a missing key fails at policy load. The intent form carries the adapter identifier, and the bundle refuses an adapter with no `external-runtime-adapter` source under `ops/src/runbook/` before any dump runs. The question is an exact-file disposable input with no glob. The attachment budget the adapter repeats in C.2 is computed from the package member list, so the number cannot drift from the files delivered; the `consult-contract` slice asserts the equality against the manifest.

**Q2: Does the enforcement complexity exceed 100 lines without justification?**
It exceeds 100 lines with justification. 112 lines added and 3 removed in `ops/lib/scripts/bundle.sh`; 87 added in `tools/test/bundle.sh`; 34 for `ops/src/stances/consult.md.tpl`; 26 across the policy manifest, the persistence manifest, `ops/bin/manifest`, and `ops/bin/template`. One profile needs an intent parser, an adapter check, a disposable input, a text block, and a manifest object, and each has an assertion in the slice.

**Q3: Was structural prevention identified as viable but deferred?**
No. An execution-decision bundle profile stays out by the manifest's own line, and the question surface stays operator-written rather than generated, because a generated question would add a render path without removing a check.

**Q4: Complexity score (1–5) and rationale:**
Score: 2
One new profile on the existing policy-driven routing, built from the existing disposable-input, stance-render, text, and manifest paths; one new stance template; one new test slice and lane; no new dependency.

**Q5: Does a SoP note record any deferred structural prevention decision?**
Not required.

## Decision

Proceed with a policy-driven consult bundle profile: the bounded question ships as an exact-file disposable input with the core dump and a consult stance, the intent names an adapter that must resolve to an external-runtime-adapter source, and the attachment budget is computed from the package member list.

## Consequence

`bash tools/test/bundle.sh` passes with five slices; `./ops/bin/bundle --profile=consult` ships the bounded question to an external runtime adapter with the attachment budget and the output surface named in the bundle, and the landed answer is validated by the DP-OPS-0275 lint mode. Allowlist enforcement requires this leaf to be present and allowlisted before certify runs when the CbC preflight is applicable.
