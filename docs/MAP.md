## 5. The Shipping Spine (Operator Chain)
*End-to-end delivery chain from topic to merge.*

Durable collaboration and fluid exploration may precede this chain. Conversation can develop experience and intent, but mutation authority begins only when captured by the proper artifact boundary.

exploration → `TOPIC.md` → `PLAN.md` → Integrator (Architect stance) → `storage/dp/intake/DP.md` → packet-authorized Worker → `RESULTS` + `CLOSING` → independent Audit → `PASS` / `FAIL` → merge or correction

* **Topic:** `storage/handoff/TOPIC.md` — latest-wins planning input.
* **Plan:** `storage/handoff/PLAN.md` — latest-wins planning output, draft input.
* **Integrator:** Performs the Architect draft stance from generated artifacts. Web UI and repo-native runtimes are equivalent when the same input and output contract is preserved; free-form Operator draft prompt text required: `0`.
* **Active DP draft:** `storage/dp/intake/DP.md` — latest-wins worker-ready operator surface.
* **Worker:** Executes the validated DP under fresh packet-scoped authority, an exact writer claim, and a DP-authorized context boundary. Worker identity and project familiarity may be durable; prior conversation grants current execution authority `0` times.
* **Packet/process identity:** `DP-OPS-XXXX` — retained in the TASK leaf chain for base packets, addendum lineage leaves for addenda, certify receipts, and telemetry. Draft dispatch allocates the next packet id from the current certified TASK packet id plus one.
* **Certify:** `ops/bin/certify` — generates `RESULTS`, emits SoP/PoW/TASK archive leaves, requires `STELA_TRACE_ID` from latest OPEN artifact.
* **Audit bundle:** `storage/handoff/AUDIT-*.txt` (initial) / `storage/handoff/AUDIT-R*.txt` (rerun) — generated by `ops/bin/bundle --profile=audit` and reviewed independently for `PASS` or `FAIL`.
* **Verdict routing:** `PASS` permits Operator commit, PR, and merge after gates. `FAIL` returns bounded findings for correction or addendum authorization, followed by an audit rerun.
* **Runtime boundary:** Roles are logical, not provider-specific. Canon and generated artifacts carry authority; unrecorded conversation does not. Generated planning, draft, Worker-dispatch, and audit artifacts are the launch prompts; free-form Operator prompt text required to start each main-lane role run: `0`.
* **Secondary lanes:** `addenda/addendum` (intervention), `execution-decision` (disposable/manual) — bounded sidepaths, not replacements for RESULTS or audit truth.
* **Delivery mechanics:** `docs/MANUAL.md#cockpit-re-entry-card`.
